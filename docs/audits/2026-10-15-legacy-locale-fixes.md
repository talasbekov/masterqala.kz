# Audited legacy/planned locale fixes (C8)

The Next and Vite clients now use their existing i18next language for the audited Payments, PriceView, DoneView and PactiveView strings. The adjacent ProgressView pilot note and step labels use the same resources. PactiveView formats the date using ru-RU / kk-KZ / en-GB, preserving the existing timestamp and timezone behavior; known planned status labels are translated and unknown statuses remain explicit raw values.

KK and EN lacked the sections used by these screens and silently fell back to Russian. This change supplies the keys actually used here in both clients, including the existing paid branch wording. It does not change the meaning of historical commercial modes, totals, payment flags, requests, transition handlers, time limits or rules. Historical direct-to-master/payment wording is intentionally preserved as legacy behavior. This is not new platform-payment implementation or full locale coverage of every old screen.

TDD: the first five actual mounted Next screen tests failed before the implementation. The final tests mount actual components with their real locale JSON, switch RU → KK → EN on the same instance, check own-locale key availability, visible translated notes/status/date, no raw keys or Russian fallback in EN, preserved master data, and no fetch/write on language switch. Nine cases in each client cover free pilot, existing paid Price/Done/Progress branches, and planned waiting/confirmed states.
