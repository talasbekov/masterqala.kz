# Desktop local entry

The desktop client is `apps/client`, normally port **4200**. Its public `/` route is a map-first urgent-order composer. The existing account overview is `/dashboard`; all private order/account routes remain guarded. `apps/site` is the informational site on **4100**, whose request CTA opens the desktop root. `apps/master` uses **4300**, `apps/operator` **4400** when started, and the separate `apps/web` mobile development surface uses **5173**.

For local builds and startup, configure `NEXT_PUBLIC_API_URL=http://127.0.0.1:3000/api/v1`, `NEXT_PUBLIC_MASTER_APP_URL=http://127.0.0.1:4300`, `API_URL=http://127.0.0.1:3000/api/v1`, `APP_URL=http://127.0.0.1:4200`, and `MASTER_APP_URL=http://127.0.0.1:4300`. Next public variables must be set before building. Production destinations remain explicitly configured; the informational site has no localhost production fallback. Use the project's existing commands and dependencies. Local verification uses FREE_PILOT, console SMS and a local test database only.

The guest composer stores only editable fields in a separate tab-scoped record. All protected navigation saves the exact current fields before starting login. Successful login may transfer the record once, without overwriting any existing owned draft or pending request. It never creates an order automatically. Creation and explicit recovery reuse the shared server-keyed implementation. Existing wizard attachments remain in the owned draft and their count is visible in the desktop composer, with a link to review them in the wizard.

The second desktop stage adds `/planned/new`, active planned request details and `/orders` history using CURRENT Figma visual structure and existing LEGACY pilot transitions. Planned drafts are owner-bound and tab-scoped; dates use Asia/Almaty. Creation persists an exact request key before POST `/planned-orders/idempotent`, and reload never automatically submits. Uploaded photos remain in their originating draft; urgent text fields may prefill a new planned draft, but single-use photo references are not copied. The history tab is stored in the URL for reload/Back. Saved-address search, the full urgent-detail redesign, comparison-screen redesign, profile, master and operator refinements remain separate work. No platform reserve, new financial model, payment integration or deployment is included.
