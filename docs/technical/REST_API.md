# REST API MasterQala.kz

Этот документ фиксирует HTTP-контракт backend MasterQala.kz.

Актуален для `main`: стек бесплатного пилота и безопасности смержен 26.07.2026.

## 1. Базовые правила

- базовый URL: `/api/v1`;
- стандартный формат запроса и ответа: JSON;
- загрузка файлов: `multipart/form-data`;
- выдача защищённых изображений и документов: бинарный поток;
- защищённые маршруты используют `Authorization: Bearer <accessToken>`;
- JWT действует 30 дней;
- суммы передаются целыми числами в тенге;
- даты и время передаются в ISO 8601;
- координаты: `lat` от `-90` до `90`, `lng` от `-180` до `180`;
- глобальная валидация NestJS использует `whitelist: true` и `transform: true`;
- неизвестные поля удаляются из body до передачи в контроллер;
- CORS разрешает только явно перечисленные origin (`credentials: true`);
- на API навешены rate-limit и security-заголовки (`src/security/*.middleware.ts`).

Пример заголовков:

```http
Authorization: Bearer eyJ...
Content-Type: application/json
```

## 2. Пользовательская модель доступа

В `User.role` сейчас существуют:

- `CLIENT` — обычный пользователь; после активации анкеты он также может выполнять действия мастера;
- `OPERATOR` — оператор административного контура.

Отдельной роли `MASTER` в `User.role` нет. Доступ мастера определяется наличием и состоянием `MasterProfile`, оффером, назначением на заявку и проверками в сервисах.

## 3. Стандартные ошибки

NestJS возвращает стандартный error body, например:

```json
{
  "statusCode": 403,
  "message": "Вывод средств недоступен в бесплатном пилоте",
  "error": "Forbidden"
}
```

| HTTP | Когда используется |
|---|---|
| `400` | невалидный DTO, телефон, файл, категория или параметры |
| `401` | отсутствует, истёк или невалиден JWT |
| `403` | нет доступа к ресурсу или функция отключена в `FREE_PILOT` |
| `404` | ресурс не найден |
| `409` | конфликт состояния, повторное действие или проигранная гонка |
| `422` | бизнес-условие не выполнено: нет мастеров, недостаточно средств/кредитов, лимит или блокировка |
| `429` | превышен любой rate-limit: глобальный 180/мин на IP, 10/10 мин на `request-code`, 30/10 мин на `verify-code`, 30/мин на загрузки — плюс 3/10 мин на номер телефона; ответ содержит `Retry-After` и `RateLimit-*` |
| `503` | неопределённый результат операции внешнего провайдера |

Машинных кодов ошибок пока нет. Клиент не должен надолго привязывать бизнес-логику к русскому тексту `message`.

## 4. Коммерческий режим

Поддерживаемые значения окружения:

- `FREE_PILOT`;
- `PAID_MOCK`;
- `PAID_LIVE` — зарезервирован, но API намеренно не запускается до подключения реального провайдера.

Если переменная отсутствует, backend использует `PAID_MOCK` для обратной совместимости. Пример окружения пилота использует `FREE_PILOT`.

### `GET /config/public`

Публичный маршрут без JWT.

Ответ бесплатного пилота:

```json
{
  "commercialMode": "FREE_PILOT",
  "paymentsEnabled": false,
  "leadCreditsEnabled": false,
  "payoutsEnabled": false
}
```

Ответ mock-платного режима:

```json
{
  "commercialMode": "PAID_MOCK",
  "paymentsEnabled": true,
  "leadCreditsEnabled": true,
  "payoutsEnabled": true
}
```

Capability-флаги определяют доступность создания новых коммерческих операций. Поведение уже созданной заявки определяется её сохранённым `commercialMode`, а не текущим env.

## 5. Служебный health-check

### `GET /health`

Публичный маршрут.

```json
{
  "status": "ok"
}
```

`GET /health` подтверждает только работу HTTP-процесса. Для оркестратора есть две
отдельные пробы:

| Метод | Маршрут | Назначение | Ответ |
|---|---|---|---|
| `GET` | `/health/live` | процесс жив | `{ "status": "alive", "checkedAt": "<ISO>" }` |
| `GET` | `/health/ready` | готов принимать трафик | `200` с деталями проверок; при неготовности — `503` |

От глобального rate-limit освобождён только `/health`; пробы `/health/live` и
`/health/ready` попадают под общий лимит 180/мин на IP.

## 6. Авторизация

### `POST /auth/request-code`

Запрашивает SMS-код.

Body:

```json
{
  "phone": "+77001234567"
}
```

Правила:

- номер нормализуется backend;
- код состоит из 6 цифр;
- срок действия — 5 минут;
- максимум 3 отправки на номер за 10 минут.

Успех: `204 No Content`.

Возможные ошибки:

- `400` — неверный формат телефона;
- `429` — превышен лимит отправок.

### `POST /auth/verify-code`

Body:

```json
{
  "phone": "+77001234567",
  "code": "123456"
}
```

Правила:

- `code` должен иметь длину ровно 6 символов;
- максимум 5 неверных попыток для актуальной записи;
- при первом успешном входе пользователь создаётся автоматически.

Ответ:

```json
{
  "accessToken": "eyJ...",
  "user": {
    "id": "uuid",
    "phone": "+77001234567",
    "name": null,
    "role": "CLIENT"
  }
}
```

## 10. Анкета мастера

### `POST /masters/application`

Требует JWT.

```json
{
  "fullName": "Иван Иванов",
  "iin": "900101123456",
  "district": "Есиль",
  "experienceYears": 5,
  "categoryIds": ["uuid"]
}
```

Ограничения:

- `fullName`: 5–150 символов;
- `iin`: ровно 12 цифр;
- `district`: 2–100 символов;
- `experienceYears`: целое число `0..60`;
- `categoryIds`: минимум один элемент; формат идентификатора на уровне DTO не
  проверяется — проверяется только существование категории (иначе `400`);
- все категории должны существовать.

Повторная отправка разрешена для ранее отклонённой анкеты или `NEEDS_INFO`. Статусы `PENDING_REVIEW` и `ACTIVE` дают `409`.

### `GET /masters/application`

Возвращает собственную анкету, категории, документы и `latestDecisionComment`.

### `POST /masters/application/documents`

Требует JWT и `multipart/form-data`.

Поля:

- `file` — JPEG, PNG или PDF;
- `type` — значение Prisma enum `DocumentType`.

Ограничения:

- максимум 10 МБ;
- сначала должна существовать анкета;
- загрузка разрешена только в `PENDING_REVIEW` или `NEEDS_INFO`.

## 11. Универсальная загрузка изображений

### `POST /uploads`

Требует JWT и `multipart/form-data`.

- поле: `file`;
- форматы: JPEG или PNG;
- размер: максимум 10 МБ.

Ответ:

```json
{
  "path": "relative/storage/path.jpg"
}
```

`path` передаётся в `photoPaths` при создании срочной или плановой заявки. Прямого публичного URL нет: файлы выдаются через защищённые маршруты заявок.

### 12.3 Создание

Body `POST /orders` расширяет preview:

| Поле | Тип | Ограничение |
|---|---|---|
| `categoryId` | UUID | обязательно |
| `lat` / `lng` | number | обязательно |
| `description` | string | обязательно, максимум 2000 |
| `address` | string | обязательно, максимум 500 |
| `district` | string | обязательно, максимум 200 |
| `entrance` | string | optional, максимум 50 |
| `floor` | string | optional, максимум 50 |
| `apartment` | string | optional, максимум 50 |
| `addressComment` | string | optional, максимум 500 |
| `photoPaths` | string[] | optional, максимум 5; элементы уникальны, каждый — `<uuid>.jpg\|png`, полученный от `POST /uploads`; файл, не прошедший карантин, даёт ошибку при создании |

Ключевые ограничения:

- одна активная срочная заявка на клиента;
- категория должна существовать;
- при отсутствии мастеров создание возвращает `422`;
- принятие защищено атомарным переходом; проигравший мастер получает `409`;
- принимать может только мастер с `PENDING`-оффером текущей попытки;
- цена работ подтверждается клиентом в течение 15 минут;
- `DONE` автоматически закрывается через 24 часа при отсутствии открытого спора.

### 12.4 Представление цены в бесплатном пилоте

Для заявки с `commercialMode=FREE_PILOT` HTTP-ответы показывают:

- `calloutPrice: 0`;
- `serviceFee: 0`;
- `freePilot: true`;
- номинальные значения могут возвращаться как `nominalCalloutPrice` и `nominalServiceFee` для аналитики и объяснения расчёта.

`workPrice` — цена работ, которую мастер предлагает после осмотра. Платформа не принимает этот платёж: расчёт происходит напрямую между клиентом и мастером.

Режим определяется сохранённым `Order.commercialMode`. Переключение env не меняет уже созданную заявку.

### 12.5 Предложение цены работ

`POST /orders/:id/propose-price`:

```json
{
  "amount": 12000,
  "comment": "Замена смесителя, материалы клиента"
}
```

- `amount` — обязательно, целое число ≥ 1;
- `comment` — optional, максимум 1000 символов; сохраняется как `workComment`.

## 13. Плановые заявки

Все маршруты требуют JWT.

### 13.1 Маршруты

| Метод | Маршрут | Инициатор | Назначение |
|---|---|---|---|
| `POST` | `/planned-orders` | клиент | создать и опубликовать заявку |
| `GET` | `/planned-orders/mine` | клиент | собственные заявки |
| `GET` | `/planned-orders/feed` | мастер | лента по категориям мастера |
| `GET` | `/planned-orders/:id` | любой аутентифицированный | получить заявку с ролевой редакцией |
| `GET` | `/planned-orders/:id/photos/:photoId` | участник/оператор | получить фото |
| `POST` | `/planned-orders/:id/bids` | мастер | оставить отклик |
| `POST` | `/planned-orders/:id/select` | клиент | выбрать отклик |
| `POST` | `/planned-orders/:id/confirm` | выбранный мастер | подтвердить готовность |
| `POST` | `/planned-orders/:id/decline` | выбранный мастер | отказаться до подтверждения |
| `POST` | `/planned-orders/:id/on-site` | назначенный мастер | начать работу |
| `POST` | `/planned-orders/:id/complete` | назначенный мастер | отметить выполнение |
| `POST` | `/planned-orders/:id/confirm-completion` | клиент | закрыть заявку |
| `POST` | `/planned-orders/:id/cancel` | клиент/назначенный мастер | отменить по state machine |

Доступ к `GET /planned-orders/:id` не ограничен участием: посторонний
аутентифицированный пользователь (включая оператора) получает редактированную
карточку — без адреса, подъезда/этажа/квартиры, фото (`photos: []`), контактов
клиента и списка откликов; `budget` виден намеренно (он публичен в ленте).
Следствие для оператора: маршрут фото ему доступен, но `photoId` через этот API
он не узнает — асимметрия со срочными заявками, где оператор видит полную
карточку.

### 13.2 Создание

```json
{
  "categoryId": "uuid",
  "description": "Установить смеситель",
  "address": "Астана, ...",
  "district": "Есиль",
  "slotStart": "2026-07-25T10:00:00+05:00",
  "slotEnd": "2026-07-25T12:00:00+05:00",
  "budget": 15000,
  "photoPaths": []
}
```

Дополнительно принимаются `entrance`, `floor`, `apartment` (каждое — optional,
максимум 50 символов) и `addressComment` (optional, максимум 500).

Ограничения:

- `slotStart` и `slotEnd` — ISO 8601;
- начало должно быть в будущем и не дальше 14 дней;
- конец должен быть позже начала;
- `budget` — optional, целое число от 0;
- `description` — максимум 2000, `address` — максимум 500, `district` — максимум 200;
- максимум 5 изображений (правила `photoPaths` — как в §12.3).

### 13.3 Отклик мастера

`POST /planned-orders/:id/bids`:

```json
{
  "price": 12000,
  "term": "Сегодня до 18:00",
  "comment": "Материалы оплачиваются отдельно"
}
```

Ограничения:

- `price`: целое число от 1;
- `term`: обязательно, максимум 200;
- `comment`: optional, максимум 1000;
- максимум 5 откликов на заявку;
- один отклик одного мастера;
- заблокированный мастер не может откликаться.

Коммерческое поведение определяется `PlannedOrder.commercialMode`:

- `FREE_PILOT` — отклик не требует баланса и не создаёт `SPEND`/`REFUND`;
- `PAID_MOCK` — отклик требует и списывает 1 lead-кредит.

Поэтому в одной ленте могут одновременно находиться бесплатные и исторические платные заявки.

### 13.4 Выбор отклика

`POST /planned-orders/:id/select`:

```json
{
  "bidId": "uuid"
}
```

Выбранный мастер должен подтвердить готовность в течение 2 часов. Заявка без единого отклика становится `EXPIRED` при наступлении `slotStart`. `DONE` автоматически закрывается через 24 часа при отсутствии спора.

До назначения сервис скрывает чувствительные данные. Телефон мастера становится доступен клиенту с `CONFIRMED`.

```json
}
```

`reason` обязателен, максимум 2000 символов.

Пояснение второй стороны, `PATCH /disputes/:id`:

```json
{
  "counterStatement": "Пояснение второй стороны"
}
```

`counterStatement` обязателен, максимум 2000 символов.

Правила:

- спор доступен в `IN_PROGRESS`, `DONE` и `CLOSED`;
- после `CLOSED` окно открытия — 48 часов;
- по заявке может существовать только один **открытый** спор (partial unique индекс в БД);
- доказательства: JPEG/PNG, максимум 10 МБ;
- пояснение добавляет только вторая сторона;
- закрытый спор нельзя дополнять.

## 17. Отзывы

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/orders/:id/review` | отзыв по срочной заявке |
| `POST` | `/planned-orders/:id/review` | отзыв по плановой заявке |

```json
{
  "rating": 5,
  "comment": "Работа выполнена хорошо"
}
```

- `rating`: целое число `1..5`;
- `comment`: optional, максимум 1000;
- одна заявка может иметь не более одного отзыва.

## 18. Оператор: анкеты мастеров

Все маршруты требуют JWT и `role=OPERATOR`.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/admin/applications?status=` | список с optional-фильтром `MasterStatus` |
| `GET` | `/admin/applications/:id` | детали анкеты |
| `GET` | `/admin/applications/:id/documents/:docId` | защищённый документ |
| `POST` | `/admin/applications/:id/decision` | решение оператора |

Body решения:

```json
{
  "decision": "APPROVE",
  "comment": "Документы подтверждены"
}
```

`decision` должен соответствовать Prisma enum `DecisionType`; `comment` optional, максимум 1000.

## 19. Оператор: споры

Все маршруты требуют JWT и `role=OPERATOR`.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/admin/disputes?status=` | список, optional `OPEN`/`RESOLVED` |
| `GET` | `/admin/disputes/:id` | детали и `commercialMode` целевой заявки |
| `POST` | `/admin/disputes/:id/resolve` | разрешить спор |

Body:

```json
{
  "refundServiceFee": false,
  "penalizeMaster": true,
  "resolutionNote": "Решение оператора"
}
```

В `FREE_PILOT` backend принудительно сохраняет `refundServiceFee=false` и не вызывает платёжный refund, потому что платформа не принимала сервисный сбор.

## 20. Оператор: заявки, мастера, пользователи

Все маршруты требуют JWT и `role=OPERATOR`. В `AuditLog` пишутся только
блокировка и разблокировка пользователя; решения по анкетам фиксируются в
`VerificationDecision`, решения по спорам — в полях `Dispute`. Сквозного
операторского журнала нет: `AuditLogService.list()` написан, но ни один
контроллер его не вызывает.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/admin/orders?type=urgent\|planned&status=&search=` | сквозной список заявок обоих типов |
| `GET` | `/admin/orders/:id?type=` | детали заявки; `type` по умолчанию `urgent` |
| `GET` | `/admin/masters?category=&district=` | мастера с производным статусом и рейтингом |
| `GET` | `/admin/users?search=` | поиск по телефону и имени |
| `POST` | `/admin/users/:id/block` | заблокировать, body — причина |
| `POST` | `/admin/users/:id/unblock` | разблокировать |
| `GET` | `/admin/withdrawals` | заявки на вывод средств |

Оператор заявки **только читает**: переназначить мастера или сменить статус нельзя,
хотя спека §2.4 это допускает.

Спланированные в этапе 6, но **не реализованные** маршруты: `GET
/admin/orders/:id/candidates`, `POST /admin/orders/:id/assign`, `GET
/admin/metrics`, `GET /admin/journal` — описаны в плане Stage 6, в коде
отсутствуют.

Блокировка сквозная: заблокированный пользователь получает `403` и на `JwtAuthGuard`,
и на `/auth/verify-code`, то есть не может ни работать, ни перевойти.

Производный статус мастера в `/admin/masters` — `блокирован до <дата>` либо
`активен · онлайн`/`активен · офлайн`. Понижение приоритета в статусе **не
отражается**: приоритета внутри волны не существует, см. [`../STATUS.md`](../STATUS.md).

## 21. Оператор: безопасность

Все маршруты требуют JWT и `role=OPERATOR`.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/admin/security/dashboard` | сводка: открытые алерты, нарушения SLA, доставки |
| `GET` | `/admin/security/alerts` | список алертов |
| `PATCH` | `/admin/security/alerts/:id` | сменить статус, body — `status` + optional `note` |
| `PATCH` | `/admin/security/alerts/:id/assignment` | назначить владельца, `assigneeUserId` (`null` — снять) |
| `GET` | `/admin/security/alerts/:id/deliveries` | история доставок уведомлений |
| `POST` | `/admin/security/alerts/:id/deliveries/retry` | повторить доставку |
| `GET` | `/admin/security/events` | лента событий аудита безопасности |

Фильтры `/admin/security/alerts`: `status`, `severity`, `ruleKey`, курсорная
пагинация через `before` + `beforeId`, `limit`.

Фильтры `/admin/security/events`: `action`, `severity` (`INFO`/`WARNING`/`HIGH`/`CRITICAL`),
`resourceType`, `resourceId`, та же курсорная пагинация.

> Таблица `SecurityAlert` создаётся миграцией, но модели в `schema.prisma` нет —
> сервис читает её сырым SQL. Подробности в [`../STATUS.md`](../STATUS.md).

## 22. Статус карантина файла

Загруженный файл проходит карантин, поэтому у каждого канала есть эндпоинт статуса.

| Метод | Маршрут |
|---|---|
| `GET` | `/uploads/:path/status` |
| `GET` | `/masters/application/documents/:id/status` |
| `GET` | `/disputes/:id/evidence/:evidenceId/status` |

Модель fail-closed: пока проверка не завершена успешно, файл не отдаётся.
Правила — в [`FILE_UPLOAD_SECURITY.md`](./FILE_UPLOAD_SECURITY.md).

## 23. Защищённые файлы

Следующие маршруты не являются публичными static URL:

- `/orders/:id/photos/:photoId`;
- `/planned-orders/:id/photos/:photoId`;
- `/disputes/:id/evidence/:docPath`;
- `/admin/applications/:id/documents/:docId`.

Перед выдачей сервис проверяет участие пользователя или роль оператора. Клиентские приложения не должны сохранять эти URL как бессрочные публичные ссылки.

## 24. Совместимость HTTP и Socket.IO

HTTP является источником полного состояния заявки. Socket.IO используется для уведомления об изменениях и ускорения интерфейса.

Для `FREE_PILOT` оба канала обязаны показывать нулевые `calloutPrice`/`serviceFee`. Контракты realtime описаны в [`WEBSOCKET_EVENTS.md`](./WEBSOCKET_EVENTS.md).

Клиент должен перечитывать ресурс через HTTP:

- после reconnect;
- после неизвестного события;
- при пропущенной последовательности переходов;
- перед необратимым пользовательским действием.
