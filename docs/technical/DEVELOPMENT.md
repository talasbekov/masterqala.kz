# Локальная разработка

## Требования

Node 20+, pnpm 9.15, Docker (для PostgreSQL с PostGIS).

## Первый запуск

```bash
docker compose up -d                  # БД :5432 и тестовая БД :5433
pnpm install
cp apps/api/.env.example apps/api/.env
cd apps/api && pnpm prisma migrate dev && pnpm prisma db seed && cd ../..
```

Затем в двух терминалах:

```bash
pnpm --filter api start:dev           # API на :3000, префикс /api/v1
pnpm --filter web dev                 # Web на :5173
```

Обе базы — образ `postgis/postgis:16-3.4`; обычный `postgres` не подойдёт, гео-запросы
матчинга упадут. Схему `pgboss` очередь создаёт сама при первом старте API — отдельной
миграции не нужно.

## Переменные окружения

`apps/api/.env`, шаблон — [`.env.example`](../../apps/api/.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | — | **Обязательна.** Строка подключения к PostgreSQL |
| `JWT_SECRET` | `dev-secret-change-me` | Подпись токенов. В проде задавать обязательно |
| `OPERATOR_PHONE` | — | Телефон оператора, создаётся сидами |
| `UPLOAD_DIR` | `./uploads` | Каталог для документов, фото и доказательств |
| `PRICING_BASE_FARE` | `2000` | Базовый тариф выезда, ₸ |
| `PRICING_PER_KM` | `150` | Тариф за километр, ₸ |
| `SERVICE_FEE_RATE` | `0.4` | Доля платформы от стоимости выезда |
| `SERVICE_FEE_MIN` | `1000` | Минимальный сервисный сбор, ₸ |
| `PGBOSS_DISABLED` | — | `1` отключает очередь. Используется в e2e |

`SERVICE_FEE_MIN` обязан быть меньше `PRICING_BASE_FARE` — иначе на минимальном заказе
компенсация мастеру уходит в ноль. Инвариант проверяется на старте и роняет приложение
с внятной ошибкой, а не молча.

## Данные из сидов

[`prisma/seed.ts`](../../apps/api/prisma/seed.ts) создаёт шесть категорий
(`plumbing`, `electrics`, `appliances`, `locksmith`, `handyman`, `other`) и оператора
с телефоном из `OPERATOR_PHONE`.

## Вход в dev

Реального SMS-шлюза нет: `ConsoleSmsSender` пишет код в лог API строкой вида
`SMS → +7…`. Берите код оттуда.

Учтите два ограничения — они настоящие и в dev тоже: код живёт 5 минут, отправок не
более 3 за 10 минут на номер, попыток ввода — 5 на код.

## Тесты

```bash
pnpm --filter api test                # unit — 46 тестов, ~4 с
ALLOW_ISOLATED_API_TESTS=1 pnpm --filter api test:e2e # destructive e2e; нужна db_test на :5433
```

Перед первым прогоном e2e накатите схему на тестовую базу:

```bash
cd apps/api && DATABASE_URL=postgresql://masterqala:masterqala@localhost:5433/masterqala_test \
  pnpm prisma migrate deploy
```

E2E ходят в отдельную базу (`masterqala_test`) и запускаются последовательно
(`--runInBand`) — они делят состояние БД. Очередь в них выключена через
`PGBOSS_DISABLED=1`, поэтому отложенные джобы не срабатывают сами: тест, который
проверяет таймаут, вызывает обработчик напрямую.

E2E очищают данные через `TRUNCATE`, поэтому требуют явного
`ALLOW_ISOLATED_API_TESTS=1` и `NODE_ENV=test`. Разрешён только PostgreSQL URL
с хостом `localhost` или `127.0.0.1`, портом `5433`, базой `masterqala_test`,
без query/hash-параметров. Скрипт `test:e2e` задаёт этот локальный URL и
`NODE_ENV=test`, но не включает разрешение на очистку автоматически. Перед
каждой очисткой дополнительно проверяются фактическое имя подключённой базы
и схема `public`. Выделенная queue-suite сохраняет собственный opt-in
`ALLOW_ISOLATED_QUEUE_TESTS=1` и базу `masterqala_urgent_queue_ci` на порту `5434`;
разрешения двух наборов тестов не взаимозаменяемы.

## Ручная проверка срочного режима

Нужны два окна браузера: A — клиент, B — мастер. Второе лучше в режиме инкогнито,
иначе окна поделят один токен.

Подготовка: мастер заранее одобрен оператором (вход под `OPERATOR_PHONE` → `/admin`),
геолокация разрешена в обоих окнах. Чтобы точки клиента и мастера гарантированно попали
в радиус первой волны, подмените координаты через DevTools → Sensors в обоих окнах
на одну точку.

1. **B:** вкладка «Работа» → тумблер «Онлайн» → индикатор соединения активен.
2. **A:** «Вызвать мастера» → категория, описание, адрес → превью «Выезд: N ₸» → создать.
3. **B:** полноэкранный оффер со звуком и таймером → «Принять».
4. **A:** степпер перешёл в «Принята», виден телефон мастера — **без перезагрузки страницы**.
5. **B:** «Еду» → «На месте» → цена 15000 + комментарий.
6. **A:** карточка цены с обратным отсчётом → «Подтвердить».
7. **B:** «Выполнено». **A:** «Подтвердить выполнение» → «Закрыта».
8. В БД: `PaymentTransaction` содержит `HOLD` и `CAPTURE` на **полную** стоимость выезда;
   `Accrual` = выезд − сервисный сбор.

Ветки, которые стоит прогнать отдельно: клиент отменяет в поиске (бесплатно); мастер
отменяет после принятия (заявка возвращается в поиск и уходит следующему); все мастера
офлайн → `NO_MASTERS` → кнопка «Повторить поиск».

## Частые проблемы

**Матчинг никого не находит.** Проверьте: мастер онлайн, у него статус `ACTIVE`,
категория заявки есть в его категориях, и координаты действительно рядом. Кандидаты
подбираются `ST_DWithin` по 3 км в первой волне.

**Заявка «зависла» в статусе.** Скорее всего API перезапускали и pg-boss ещё не поднял
воркеры, либо очередь отключена переменной. Отложенные джобы переживают рестарт —
подождите цикл.

**`409` на действии.** Это не баг, а атомарный гейт: статус уже изменился. Перечитайте
заявку и повторите от актуального состояния.
