# MasterQala.kz — Второй мозг (Obsidian Vault)

Это хранилище Obsidian живёт внутри репозитория MasterQala.kz (маркетплейс
бытовых услуг: заказчики ↔ мастера, срочный и плановый режимы). Все записи —
сырые материалы, структурированные заметки, готовые документы — ведутся здесь
как обычные Markdown-файлы.

## Структура

- `RAW/` — сырые, необработанные материалы: статьи, транскрипты встреч и
  созвонов, интервью с мастерами/заказчиками, черновики, клипы из веба (сюда же
  смотрит Web Clipper). Ничего не удалять — только переносить/ссылаться после
  обработки.
- `WIKI/` — структурированные, связанные заметки по темам (продукт, рынок КЗ,
  конкуренты, фичи, пользовательские исследования, юнит-экономика, пилот,
  Kaspi-платежи и т.д.). Каждая заметка — одна тема, с двусторонними ссылками
  `[[wiki-style]]` на связанные заметки.
- `OUTPUT/` — готовые результаты: отчёты, питчи, планы, презентации, сценарии
  онбординга мастеров, документы для внешнего использования (инвесторы,
  партнёры, пилотные ЖК).
- `README.md` — живое оглавление хранилища. Начинай поиск контекста отсюда.
- `LOG.md` — журнал: что и когда обработано.

## Границы с остальным репозиторием

- `../docs/` — инженерная и продуктовая документация (спека, архитектура,
  безопасность, статусы). Это источник истины по системе — не дублируй её в
  `WIKI/`, а ссылайся обычными относительными ссылками.
- `../MasterQala-design-prototype/`, `../design-artifacts/`, `../ds-bundle/` —
  выгрузки дизайна, не трогать вручную.
- Код (`../apps/`, `../packages/`) хранилище не описывает — для этого есть
  `docs/technical/`.

## Правила для ИИ

1. Перед началом работы прочитай `README.md`, чтобы понять текущую карту знаний
   (это экономит токены — не нужно сканировать всё хранилище).
2. Новый сырой материал в `RAW/` → прочитать → выделить ключевые мысли →
   создать/обновить связанные заметки в `WIKI/` → обновить `README.md` →
   добавить запись в `LOG.md`.
3. Имена файлов: `kebab-case` или человекочитаемые заголовки без спецсимволов,
   на языке контента (обычно русский). Один файл — одна тема/сущность.
4. Связывай заметки между собой через `[[Название заметки]]`. Избегай
   заметок-сирот: у каждой новой заметки должна быть минимум одна входящая или
   исходящая ссылка.
5. Не переписывай `RAW/` — это архив источников. Обработка создаёт новые файлы
   в `WIKI/`, а не изменяет сырьё.
6. После каждой значимой сессии работы — короткая запись в `LOG.md` в формате:
   `- [YYYY-MM-DD HH:MM] <что сделано, какие файлы затронуты>`.
7. Планы, эпики и техническую документацию по разработке оформляй в `../docs/`
   (там уже есть структура и правила статусов утверждений) — хранилище для
   мыслей и материалов, а не параллельная техдока. Если заметка из `WIKI/`
   дозрела до инженерного решения — переноси суть в `docs/` и оставляй в
   заметке ссылку.
